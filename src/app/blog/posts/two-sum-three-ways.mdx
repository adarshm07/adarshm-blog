"Given an array and a target, return the indices of the two numbers that
add up to the target." Two Sum is the first problem almost everyone meets,
and it's a perfect miniature lesson: the same tiny problem has three
solutions, each one a different [DSA pattern](/blog/dsa-patterns), each
trading memory for time in a different way.

```javascript
twoSum([2, 7, 11, 15], 9); // [0, 1]  because 2 + 7 = 9
```

## Approach 1: brute force

Check every pair. Two nested loops, no cleverness:

```javascript
function twoSum(nums, target) {
  for (let i = 0; i < nums.length; i++) {
    for (let j = i + 1; j < nums.length; j++) {
      if (nums[i] + nums[j] === target) return [i, j];
    }
  }
  return [];
}
```

- **Time:** O(n²) — every pair
- **Space:** O(1)

It always works and it's the right *first* answer in an interview: state
the obvious solution, then improve it. The improvement comes from noticing
the inner loop is really asking one question — *"have I already seen
`target - nums[i]`?"* — and a nested scan is a slow way to answer it.

## Approach 2: sort + two pointers

If the array were **sorted**, we could put one pointer at each end and let
their sum guide us: too big → move the right pointer down, too small →
move the left pointer up. This is the
[two-pointer pattern](/blog/dsa-patterns#two-pointers).

<TwoSumTwoPointer />

```javascript
function twoSum(nums, target) {
  // pair each value with its original index before sorting
  const indexed = nums.map((value, index) => ({ value, index }));
  indexed.sort((a, b) => a.value - b.value);

  let lo = 0;
  let hi = indexed.length - 1;
  while (lo < hi) {
    const sum = indexed[lo].value + indexed[hi].value;
    if (sum === target) return [indexed[lo].index, indexed[hi].index];
    if (sum < target) lo++;
    else hi--;
  }
  return [];
}
```

- **Time:** O(n log n) — dominated by the sort
- **Space:** O(n) to keep original indices (or O(1) if the problem only
  asks whether a pair exists and you may sort in place)

Each step throws away a whole row or column of the brute-force grid,
because sorted order guarantees the discarded direction can't contain the
answer — the same insight behind
[binary search](/blog/binary-search-and-bst). This is the go-to when the
input is already sorted, or when you need the *values* rather than the
original indices.

## Approach 3: hash map

The two-pointer version pays O(n log n) for sorting. But we don't actually
need order — we need fast "have I seen this number?" lookups, and that's
exactly what a [hash map](/blog/hash-maps-under-the-hood) gives us in O(1).
One pass: for each number, check whether its **complement**
(`target - num`) is already in the map.

```javascript
function twoSum(nums, target) {
  const seen = new Map(); // value -> index
  for (let i = 0; i < nums.length; i++) {
    const complement = target - nums[i];
    if (seen.has(complement)) return [seen.get(complement), i];
    seen.set(nums[i], i);
  }
  return [];
}
```

- **Time:** O(n) — a single pass
- **Space:** O(n) — the map

The key move: **check before you insert**. Checking first guarantees the
two indices are different (you never match a number with itself), and it
means you only ever store numbers you've actually passed.

The progression is the whole point: brute force asks a question slowly,
two pointers exploits *order* to answer it, and the hash map trades memory
to answer it instantly. Recognizing "have I seen its complement?" as a
hash-map cue is a pattern you'll reuse in dozens of problems — 3Sum, "two
sum in a BST", "subarray sum equals k", and more. Back to the
[full pattern catalog](/blog/dsa-patterns).
