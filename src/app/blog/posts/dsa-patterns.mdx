After grinding through enough problems, you notice something reassuring:
there aren't actually a thousand distinct problems. There are maybe a dozen
**patterns**, dressed in different stories. "Find the longest substring…",
"detect a cycle…", "return all combinations…" — once you recognize the
shape, the solution is nearly a template.

This post is a catalog of the patterns worth knowing, each with the cue
that signals it, a short example, and its cost. A few have full deep-dive
posts of their own with multiple approaches and animations — I've linked
those inline.

## Two pointers

**Cue:** a sorted array (or two sequences) where you're looking for a pair,
a triple, or a merge. Instead of nested loops, walk two indices toward each
other and let their relationship decide which one moves.

```javascript
// Is there a pair summing to target in a sorted array?
function hasPair(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo < hi) {
    const sum = nums[lo] + nums[hi];
    if (sum === target) return true;
    sum < target ? lo++ : hi--;
  }
  return false;
}
```

Because the array is sorted, moving a pointer discards a whole set of pairs
that can't be the answer — O(n) instead of O(n²). Deep dive:
[Two Sum, Three Ways](/blog/two-sum-three-ways) walks the same problem from
brute force down to this.

## Sliding window

**Cue:** the longest / shortest / best **contiguous** subarray or substring
satisfying a condition. Maintain a window `[start, end]`, expand on the
right, and shrink from the left when the window becomes invalid.

```javascript
// Longest subarray with sum <= k (non-negative numbers)
function longestUnder(nums, k) {
  let start = 0, sum = 0, best = 0;
  for (let end = 0; end < nums.length; end++) {
    sum += nums[end];
    while (sum > k) sum -= nums[start++];
    best = Math.max(best, end - start + 1);
  }
  return best;
}
```

Each element enters and leaves the window once, so an O(n²) re-scan
becomes O(n). Deep dive:
[Longest Substring Without Repeating Characters](/blog/longest-substring-without-repeating)
with an animated window.

## Fast & slow pointers

**Cue:** a linked list or a sequence where you need to detect a cycle, find
the middle, or locate a loop's entry. Two pointers move at different speeds;
if there's a cycle, the fast one laps the slow one.

```javascript
function hasCycle(head) {
  let slow = head, fast = head;
  while (fast && fast.next) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true; // they met inside the loop
  }
  return false;
}
```

O(n) time, O(1) space — no visited-set needed. Also called Floyd's
tortoise and hare.

## Prefix sums

**Cue:** many range-sum queries, or "count subarrays that sum to k". Precompute
a running total so any range sum is one subtraction.

```javascript
// Number of subarrays summing to k
function subarraySum(nums, k) {
  const counts = new Map([[0, 1]]); // prefix sum -> how many times seen
  let sum = 0, total = 0;
  for (const n of nums) {
    sum += n;
    total += counts.get(sum - k) ?? 0; // a prior prefix completes a subarray
    counts.set(sum, (counts.get(sum) ?? 0) + 1);
  }
  return total;
}
```

This combines prefix sums with a [hash map](/blog/hash-maps-under-the-hood)
to hit O(n) — a pairing that shows up constantly.

## Binary search

**Cue:** a sorted array, *or* a monotonic answer space ("smallest value that
works"). Halve the search range every step.

```javascript
function search(nums, target) {
  let lo = 0, hi = nums.length - 1;
  while (lo <= hi) {
    const mid = lo + ((hi - lo) >> 1);
    if (nums[mid] === target) return mid;
    nums[mid] < target ? (lo = mid + 1) : (hi = mid - 1);
  }
  return -1;
}
```

O(log n). The real skill is spotting binary search when there's no array in
sight — "minimum capacity to ship in D days" is binary search on the answer.
Deep dive: [Binary Search and BSTs](/blog/binary-search-and-bst).

## BFS (breadth-first search)

**Cue:** shortest path in an unweighted graph or grid, or level-by-level
traversal. Use a queue; nodes come out in order of distance from the start.

```javascript
function shortestPath(graph, start, goal) {
  const queue = [[start, 0]];
  const visited = new Set([start]);
  while (queue.length) {
    const [node, dist] = queue.shift();
    if (node === goal) return dist;
    for (const next of graph[node]) {
      if (!visited.has(next)) {
        visited.add(next);
        queue.push([next, dist + 1]);
      }
    }
  }
  return -1;
}
```

BFS finds the fewest-edges path because it explores all distance-1 nodes
before any distance-2 node. (For large graphs, use a real queue with a head
pointer — `Array.shift` is O(n).)

## DFS (depth-first search)

**Cue:** explore all paths, detect connected components, topological sort,
or anything tree-shaped. Go deep first, via recursion or an explicit stack.

```javascript
function numIslands(grid) {
  let count = 0;
  const sink = (r, c) => {
    if (r < 0 || c < 0 || r >= grid.length || c >= grid[0].length || grid[r][c] === '0')
      return;
    grid[r][c] = '0'; // mark visited
    sink(r + 1, c); sink(r - 1, c); sink(r, c + 1); sink(r, c - 1);
  };
  for (let r = 0; r < grid.length; r++)
    for (let c = 0; c < grid[0].length; c++)
      if (grid[r][c] === '1') { count++; sink(r, c); }
  return count;
}
```

Each cell is visited once → O(rows × cols). BFS and DFS visit the same
nodes; the choice is shortest-path (BFS) vs. exhaustive exploration (DFS).

## Backtracking

**Cue:** generate **all** permutations, combinations, or subsets — anything
where you build a candidate incrementally and undo choices that don't pan
out. DFS over a decision tree, with a "choose → recurse → un-choose" spine.

```javascript
function subsets(nums) {
  const result = [];
  const backtrack = (start, path) => {
    result.push([...path]);          // every prefix is a valid subset
    for (let i = start; i < nums.length; i++) {
      path.push(nums[i]);            // choose
      backtrack(i + 1, path);        // explore
      path.pop();                    // un-choose
    }
  };
  backtrack(0, []);
  return result;
}
```

Exponential by nature (there are 2ⁿ subsets, n! permutations) — the art is
**pruning** branches early so you don't explore dead ends.

## Top-K with a heap

**Cue:** "the k largest / smallest / most frequent", or a running median.
A heap keeps just the k relevant elements instead of sorting everything.

```javascript
// k largest: keep a min-heap of size k; evict the smallest when it overflows
// (assume MinHeap with push/pop/peek/size)
function kLargest(nums, k) {
  const heap = new MinHeap();
  for (const n of nums) {
    heap.push(n);
    if (heap.size() > k) heap.pop(); // drop the smallest of the k+1
  }
  return heap.toArray(); // the k largest remain
}
```

O(n log k) instead of O(n log n) for a full sort — a real win when k ≪ n.
The heap machinery itself is the same one behind
[heap sort](/blog/quick-sort-and-heap-sort).

## Dynamic programming

**Cue:** overlapping subproblems and optimal substructure — "count the ways",
"minimum cost to", "longest … subsequence". Solve each subproblem once and
reuse the answer.

```javascript
// Classic: climbing stairs (1 or 2 steps) — how many ways to the top?
function climbStairs(n) {
  let prev = 1, curr = 1;
  for (let i = 2; i <= n; i++) {
    [prev, curr] = [curr, prev + curr]; // ways(i) = ways(i-1) + ways(i-2)
  }
  return curr;
}
```

The naive recursion is O(2ⁿ) because it recomputes the same subproblems;
memoizing (top-down) or tabulating (bottom-up) collapses it to O(n). DP is
the deepest pattern here and deserves its own series — but every DP problem
starts with the same question: *what's the smallest subproblem, and how does
a bigger one build on it?*

Don't memorize solutions — memorize **cues**. When a new problem arrives,
run down the signals: is the input sorted? contiguous ranges? a graph? all
combinations? The pattern you match narrows a blank page down to a template
you already know. From there it's just filling in the details — and the
deep-dive posts ([Two Sum](/blog/two-sum-three-ways),
[Longest Substring](/blog/longest-substring-without-repeating),
[Binary Search](/blog/binary-search-and-bst)) show what that looks like end
to end.
